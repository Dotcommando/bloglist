# Final boundaries and failure ownership

Current contracts remain authoritative; [audit](../../../audits/0.15.2-addons-calibration-deployment-hooks.md)
maps the 38 operations and actual methods. [Verification](50-verification.md)
owns the canonical inventory and executed RED/GREEN evidence.

- Calibration recommendations require exact nonempty positive page/API evidence;
  zero-share targets need no measurement. Original resources are journalled as
  complete exclusive data before any change; failed preparation preserves allocation
  and permits a clean retry. Existing restoration-required state/journal stays durable.
- Hook ordering captures the complete binding set within transaction/session/fence.
  Known no-effect command rejection remains Failed and may use safe skip; genuine
  unknown effects still require receipts/reconciliation. Fatal abort failure keeps
  both causes and stops host replay.
- Worker completion fences messages, requests cooperative read cancellation and
  settles owned query/termination work. CPU timeout and I/O cleanup are distinct;
  uncancellable query ports remain awaited. Unexpected late errors propagate;
  expected cancellation can preserve an already completed result.
- Deployment health uses the independent backend endpoint. Permit cleanup releases
  code-owned handles/locks even if marker removal fails; the retained marker still
  excludes restore until the next successful pass. Confirmed uploads are not repeated.
- Add-on installation retains immutable claims, both primary/disposal errors and
  failed private cleanup targets. A later preparation repairs cleanup before more
  downloads. Invalid created runtimes invoke their provided disposer. Availability
  keeps the established 503 outcome and real private cause, without fake migration advice.
- The registered catalogue is an outbound adapter behind its existing neutral port;
  infra composes it. No new business abstraction, provider-specific inward type,
  fallback, authority, schema rollback, ADR policy or operator JS-object workflow.

Exhaustive combinations of unsupported/permanent faults are not claimed. Actual
private storage or dependency failure remains a truthful operation failure, with
the existing guarded retry/reconciliation contract and code-owned resource state.
