# Решения по конфликтам прав и интерфейса

Исходные сценарии перечислены в [таблице для обсуждения](interface-access-decisions.md).

## Редактирование по прямой ссылке

Для открытия черновика требуется `cms.pages.read` на эту страницу, для
сохранения также требуется `cms.pages.update`. `cms.pages.list` даёт доступ к
дереву. Если право чтения отсутствует, при открытии ссылки CMS предлагает
запросить его у администратора сайта.

В настройках роли рядом с выданным правом изменения появляется подсказка о
чтении, пока в этой роли не выбрана ни одна область `cms.pages.read`.
Запись по API с `cms.pages.update` возвращает HTTP 200 и `{"saved":true}`,
если право чтения не охватывает данную страницу. При доступе к чтению ответ
содержит сохранённый черновик. См. [проверки](../page-edit-access/40-cases.md).

## Создание страницы без управления URL

| Права и ситуация | Решение |
| --- | --- |
| Есть `cms.pages.create`, отсутствует `cms.urls.materialize` | Кнопка «+» открывает обычный черновик. Поле H1 обязательно. CMS назначает URL по H1 на языке страницы в одной транзакции с созданием черновика. |
| Есть право создать страницу, выбран существующий родитель в дереве страниц | CMS берёт префикс из действующего маршрута родительской страницы того же сайта. Если у родителя адреса ещё нет, можно выбрать корень или другого родителя. |
| В запросе указан адрес вручную или выбрана виртуальная папка в URLs | Для ручного выбора URL и входа через виртуальную папку требуется `cms.urls.materialize`. Само создание страницы через API принимает идентификатор родительской страницы. |
| В URLs выбрана виртуальная папка | «Создать страницу по адресу /blog/» подставляет путь выбранной папки. Ссылка видна только при наличии всех трёх прав: `cms.urls.list`, `cms.pages.create` и `cms.urls.materialize`. |
| Адрес занят страницей, редиректом или виртуальной папкой | CMS пробует суффиксы `-2`, `-3` и далее, сохраняя существующие маршруты. |
| Есть право публикации и уже назначен URL | Редактор может опубликовать страницу по назначенному адресу. Доступ к публикации определяется отдельным Action. |

Таблицы находятся в «Настройки → Транслитерация». Изменения относятся к одному сайту и используются при назначении новых адресов. Пустая замена удаляет символ. По умолчанию прописные буквы заменяются строчными, дефисы и тире с пробелами заменяются дефисом, знаки препинания удаляются. Правила замены допускают латиницу, цифры и дефисы. Переключатель объединения последовательных дефисов включён по умолчанию. Существующие маршруты сохраняются. Если после транслитерации H1 не содержит букв латиницы или цифр, редактору нужно исправить заголовок.

На чтение и сохранение таблиц распространяются `cms.site-settings.read` и `cms.site-settings.update`. По умолчанию доступны русский, английский, французский, греческий, немецкий, испанский, итальянский, польский, чешский и португальский. Кастомные замены хранятся в настройках сайта и входят в его дамп. Смена языка интерфейса влияет на подписи таблицы. Выбор правил для адреса определяется языком страницы.

CMS проверяет новый маршрут через `cms.routing.change.check` до записи. Если за это время адрес заняли или изменилась подходящая папка, транзакция отклоняется. Редактор может повторить сохранение того же черновика после отказа сервера.

## Рекомендации по 21 сценарию для 0.16.0

Ниже описано рекомендуемое поведение интерфейса. Фактические права и области
проверяет сервер. Каждое разрешение выдаётся явно и целиком. В редакторе роли
показываем зависимость рядом с выданным действием, которому не хватает другого
права. В рабочем разделе даём одну подсказку рядом с ожидаемым действием или
вместо недоступной панели. Подсказка называет недостающую возможность, говорит,
что можно сделать сейчас, и при необходимости направляет к администратору
сайта. Имена и адреса в ней берём из данных, доступных пользователю.

### Страницы, TV и JSON-LD

| Сценарий | Вердикт и подсказка |
| --- | --- |
| **1. Перемещение страниц.** Есть `cms.pages.set-position`, отсутствует `cms.pages.list`. | Оставляем открытие страницы по прямой ссылке по её обычным правам. Перетаскивание, выбор родителя и изменение позиции из дерева требуют доступного списка. Рядом с настройкой положения на открытой странице показываем «Чтобы выбрать родителя или изменить порядок в дереве, нужен доступ к списку страниц». В роли предлагаем проверить область списка, достаточную для нужных исходных страниц и родителей. |
| **2. Редактирование черновика без настроек публикации.** Есть `cms.pages.update`, отсутствует `cms.publication.page-options`. | При наличии `cms.pages.read` открываем черновик и даём сохранить его. Скрываем элементы, которым нужны данные панели публикации, в том числе выбор шаблона и URL и настройки кеширования в этой панели. Публичный статус из другого разрешённого источника показываем только в пределах его данных. Действия просмотра опубликованного Markdown и JSON-LD проверяют свои права. Подсказка в редакторе «Черновик можно сохранить. Чтобы увидеть настройки и сведения о публикации этой страницы, запросите доступ к ним». |
| **3. Публикация сохранённой страницы.** Есть `cms.publication.publish-page`, отсутствует `cms.pages.create` для новой страницы или `cms.pages.update` для существующей. | «Сохранить и опубликовать» показываем при праве на соответствующее сохранение и публикацию. Для существующей страницы с доступной карточкой и готовыми настройками предлагаем отдельное действие «Опубликовать сохранённый черновик». Оно работает с сохранённым состоянием страницы и назначенным URL. Рядом пишем «На сайт попадёт последняя сохранённая версия». Если шаблон или адрес ещё нужно назначить, называем недостающую настройку и направляем к человеку, который может её изменить. Для новой несохранённой страницы публикация требует сначала создать черновик. |
| **4. Общесайтовые сведения при ограниченных правах на страницы.** Область страниц «Свои» или «Группы», для `cms.publication.site-options` или `cms.urls.list` выдано «Все». | Показываем данные, полученные по соответствующему общесайтовому праву. Настройки публикации возвращают, среди прочего, идентификаторы страниц и их рабочие и публичные адреса. Каталог URLs может также показать название и статус из сводки. Активная ссылка на редактор требует чтения конкретной страницы. Рядом с общесайтовым разрешением в роли предупреждаем «Это право показывает сведения обо всём сайте, включая страницы вне области “Свои” или “Группы”». Для роли, которая должна работать только со своим разделом, рекомендуем оставить такое разрешение незаданным. |
| **5. Чтение TV-значений.** Есть `cms.template-variables.list` и `cms.template-variables.read-page`, отсутствует `cms.template-variables.save-page`. | Показываем значения и подписи полей в открытой странице в режиме чтения. Остальные доступные поля черновика можно сохранить. У группы TV показываем «Значения доступны для просмотра. Чтобы их изменить, запросите право сохранения TV-полей страницы». |
| **6. Чтение JSON-LD.** Есть `cms.json-ld.list`, отсутствует `cms.json-ld.save`. | Показываем связанные профили на доступной странице или шаблоне и открываем определение профиля в режиме чтения. Изменение профиля и его привязок выполняется в разделе JSON-LD по `cms.json-ld.save`. Подсказка в профиле «Профиль доступен для просмотра. Чтобы изменить его или его привязки, запросите право сохранения JSON-LD». Поля страницы, из которых профиль берёт значения, редактируются по обычным правам этих полей. |
| **7. Изображение Open Graph без доступа к библиотеке.** Страницу можно изменить, отсутствует `cms.files.list`. | Показываем сохранённую ссылку или имеющееся значение изображения и сохраняем его при записи других полей. Селектор библиотеки недоступен. Приватной миниатюре дополнительно нужно чтение содержимого. У поля пишем «Чтобы выбрать изображение из библиотеки, запросите доступ к списку файлов». |
| **8. Только Markdown или JSON-LD страницы.** Выдано лишь действие просмотра Markdown или предпросмотра JSON-LD. | Оставляем эти действия в контексте доступной страницы. Само разрешение на просмотр результата не открывает раздел «Страницы» или отдельный экран по прямой ссылке. В настройках роли поясняем «Чтобы открыть этот просмотр в админке, выдайте чтение нужных страниц». Дерево требуется только для выбора страницы из списка. |

### Шаблоны, чанки и сниппеты

| Сценарий | Вердикт и подсказка |
| --- | --- |
| **9. Запись исходника без пересборки сайта.** Отсутствует `cms.publication.publish-site`. | Основное действие — «Сохранить черновик». «Сохранить и применить» требует записи исходника и пересборки сайта. После сохранения пишем «Черновик сохранён. Чтобы изменения появились на сайте, попросите администратора с правом пересборки применить их». При наличии права у действия применения явно указываем, что оно пересобирает сайт. |
| **10. Сборка превью без доступа к его результату или странице.** | Селектор показывает только доступные из разрешённых данных страницы, подходящие для этого исходника. Включаем кнопку и открываем iframe, когда доступны подходящая страница, действие генерации нужного исходника (`cms.templates.preview`, `cms.chunks.preview` или `cms.snippets.preview`) и `cms.rendering-previews.read`. Если не хватает доступа к результату, пишем «Для предпросмотра нужен доступ к готовому превью». Если не хватает доступа к странице, пишем «Для предпросмотра нужна доступная страница, где используется этот исходник». Эти подсказки показываем в панели вместо пустого селектора или iframe. |
| **11. Переходы из списка использований.** Найдены страницы или исходники в других разделах. | Оставляем сведения, разрешённые ответом поиска использований. Название становится ссылкой, когда известно, что пользователь может читать конкретный целевой объект. Остальные строки отображаем текстом и даём одну подсказку под списком «Для перехода к объекту нужен доступ к его чтению». |

### Файлы

| Сценарий | Вердикт и подсказка |
| --- | --- |
| **12. Загрузка или создание папки без `cms.files.list`.** | Открываем «Файлы» с пояснением вместо дерева и форм записи. Обе операции требуют актуальной версии библиотеки даже в корне. Показываем «Для загрузки файла или создания папки нужен доступ к списку файлов». Рядом с выданным правом в роли даём ту же зависимость. Загрузка в корень без просмотра библиотеки потребует отдельного согласованного сценария API. |
| **13. Перемещение или удаление без `cms.files.usages`.** | По доступной карточке файла можно просмотреть метаданные. Перетаскивание, переименование, поля перемещения и удаление через интерфейс ждут права проверки использований и соответствующего права записи. У действий пишем «Чтобы переименовать, переместить или удалить файл, нужен доступ к проверке его использований» с перечислением только выданных действий. Проверку сохраняем и для перехода к подтверждению принудительного удаления. |
| **14. Перемещение с обновлением ссылок.** `cms.files.move` затрагивает страницы и действующую публикацию. | После проверки показываем, какой адрес меняется, какие использования найдены и что сделает «Обновить ссылки». Объясняем, что найденные ссылки в черновиках и действующей публикации могут измениться сразу; сохранённые исторические версии сохраняют свои адреса. Это эффект уже выданного действия перемещения. Ссылки на редакторы включаем только при чтении соответствующего объекта. В роли отдельно предупреждаем о влиянии действия на страницы и действующую публикацию. |
| **15. Список без содержимого.** Есть `cms.files.list`, отсутствует `cms.files.read-content`. | Показываем доступные имя, размер, тип и другие метаданные, для списка используем значок типа. Приватные миниатюры, скачивание оригинала и открытие производных требуют чтения содержимого. В карточке пишем «Чтобы открыть или скачать файл, запросите доступ к содержимому файлов». |

### URLs

| Сценарий | Вердикт и подсказка |
| --- | --- |
| **16. Изменение маршрута без списка или поиска.** Отсутствует `cms.urls.list` или `cms.urls.suggest`. | Без списка показываем в разделе «Для выбора маршрута нужен доступ к каталогу URLs». При наличии списка открываем карточку и показываем уже назначенного родителя или цель. Без подсказок поиска отключаем только выбор нового объекта и поясняем «Для выбора другого родителя или цели нужен доступ к поиску URLs». Разрешённые изменения с сохранением текущего родителя или цели оставляем там, где это поддерживает операция. |
| **17. Связь URL со страницей без `cms.pages.read`.** | Показываем название и прочие сведения о странице, уже полученные из разрешённого каталога URLs. Переход в редактор требует чтения конкретной страницы. У связи пишем «Чтобы открыть черновик, запросите право чтения этой страницы». |
| **18. Изменение маршрутов без `cms.urls.publish`.** | Разрешённые изменения работают по контракту маршрутизации. При успешном автоматическом применении подтверждаем действующее изменение. При сохранении с ожидающим применением пишем «Маршрут сохранён. Чтобы применить его, нужен администратор с правом публикации маршрутов». Кнопку «Применить маршруты» даём по `cms.urls.publish`, чтобы продолжить с уже сохранённого состояния. |

### Настройки, Hooks и аддоны

| Сценарий | Вердикт и подсказка |
| --- | --- |
| **19. Чтение настроек без сохранения или пересборки.** | `cms.site-settings.update` открывает редактирование и сохранение. При его отсутствии показываем значения для чтения и поясняем, где запросить доступ. `cms.publication.publish-site` отдельно открывает «Пересобрать сайт», в том числе пользователю с настройками только для чтения. Перед пересборкой поясняем «Сайт будет пересобран по сохранённым настройкам». При отсутствии права на пересборку подсказку показываем в том месте, где она помогает завершить уже сделанные изменения. |
| **20. Создание обработчика без `cms.hooks.save-subscription`.** | Даём создать обработчик, если выдано право его создания. «Создать и назначить» требует обоих прав, а «Назначить» существующий обработчик требует права сохранения подписки. У независимого создания сообщаем «Обработчик можно сохранить. Чтобы назначить его на событие, запросите право управления подписками». После сохранения подтверждаем, что обработчик создан и ждёт назначения. |
| **21. Навигация и действия аддона с несколькими доменами.** | Аддон явно связывает пункт меню, вложенный экран и каждую кнопку с нужными Action. Пункт аддона показывается, если на подключённом сайте доступен хотя бы один явно привязанный экран. В доступном экране аддон объясняет, какого права не хватает для конкретной операции, по тем же правилам, что и CMS. При отсутствующей привязке делегированный экран недоступен. В управлении аддонами администратору сайта показываем «Для этого экрана разработчик аддона ещё не настроил права». Это требование к интеграции интерфейса в дополнение к [контракту регистрации Actions](../../../addon-development/authorization.md). |

Для пункта 21 CMS публикует Actions вместе с подтверждённой версией аддона.
В редакторе роли одно разрешение сохраняется по ID, даже если действие показано
в нескольких доменах. Аддон получает проверенные права пользователя для
выбранного сайта, а CMS проверяет доступ к записи повторно в её транзакции.
Подсказки показываются в доступных экранах рядом с операциями, на которые у
пользователя нет права. Привязки и область задаёт разработчик аддона.

При реализации применяются [контракт авторизации](../../../arch/admin-authorization.md),
[контракт файлов](../../../arch/site-files.md), [контракт URLs](../../../arch/url-workspace.md)
[контракт редактора исходников](../../../arch/rendering-element-editing.md) и
[контракт JSON-LD](../../../arch/markdown-and-json-ld.md#json-ld-operations-and-persistence).
