# Runtime-bound authority

Use the package's exact method/template inventory and the runtime's corresponding
route inventory. Select the installed handler and its Action together. Protected
admission checks the authenticated actor's site authority before consuming a
body. A runtime receives trusted request scope through its host API and uses
the host's transactional guard alongside its existing connection fence.

Treat catalog publication as part of confirmed activation. Keep candidate package
bytes immutable and hide them from role management until activation succeeds.
Bind the policy to the selected digest and reject nonmatching admission. For
compatible overlap, only unchanged authorization boundaries may keep serving
under the same Action identity. Use Exclusive for a removed or widened boundary.
Use catalog and scope records shared with core CMS. Domain membership affects
display and does not grant access.

Menu visibility and asset admission use the bound screen's Action IDs. A control
uses the same IDs as its endpoint. Guard direct routes and private assets. Browser
state is advisory and cannot authorize an operation after role revocation.
