# Design

The named output change journal records changed file IDs and obsolete relative
paths alongside the guarded desired catalog version. An installer reloads the
journal under the site writer lock. It stages owned content privately before
touching public names, then applies the individual path changes. Ready public
bytes are replaced by renaming a prepared file in the same site directory.
Reapplying the same journal is safe after interrupted public filesystem writes.
The legacy journal continues through the existing full-projection path.

Site authority and upload admission remain with the existing entry points.
Projection validates paths through the site-owned checked-path adapter and
asserts private content ownership before streaming. The journal is generated by
the store from validated catalog versions, with no path supplied by the caller
to the filesystem adapter. The named filesystem and MongoDB commit still have
separate failure boundaries.

The November 25 follow-up stages the proposed normalized file row in the
existing journal. The active row remains readable until named installation
completes. Promotion changes just that row, then the journal records the
remaining cleanup. A public request looks up the path in the active catalog
and pins its immutable content while preparing the response.

The administration browses folders and contents separately, and SDK lookups
fetch the requested IDs in one batch. Add-on packages can declare owned file
references. Admission validates assignments inside the add-on transaction and
shares the media fence with ordinary deletion. A portable restore resolves
the archived logical address to the target site's ID.

The audit correction uses a unique target address for cross-site add-on
restores and prefers the existing ID on the source site. Missing references
remain in the archive's business data and are identified in its file mapping.
Cross-site omission is an explicit import choice subject to the add-on's
collection validator.

The file revision is recorded in an existing normalized row. Mutation
admission checks that row inside the site transaction and can retry the site
fence after unrelated writes. Move reference plans reuse the archived addresses
and output keys. They promote with the changed file, then complete under local
writer exclusion after checking current ownership of the source addresses.
