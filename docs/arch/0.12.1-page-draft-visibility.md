# CMS 0.12.1: Page editor status and unpublished changes

Requested on 2026-11-10. Target release: **0.12.1**.

## Observable behavior

Show a persistent draft indicator beside the page in the Pages left drawer and
in the page editor header. The editor indicator remains visible when switching
between Main, SEO, Open Graph and TV panels.

Distinguish these states explicitly:

- A page without an active public version: **Not published**
  (Russian: **Страница не опубликована**).
- A page already available on the site whose saved draft differs from its active
  public version: **Unpublished changes**
  (Russian: **Есть неопубликованные изменения**). Explain that the site still
  serves the previous published version.
- A page whose saved draft matches its active public version: no unpublished
  changes indicator; retain its ordinary publication status.

Do not communicate draft state through color alone. Pair the drawer marker with
an accessible textual description and show a readable status in the editor.
Keep this saved-draft status distinct from unsaved edits in the current form.
Place the draft icon immediately before the drawer's existing publication-status
dot. The dot continues to indicate publication; the separate icon indicates
saved unpublished changes. Both may appear together for a public page with edits.

In the editor, use an explicit primary state: **Совпадает с версией на сайте**,
**Есть неопубликованные изменения** (with a changed-field count), or
**Страница ещё не опубликована**. A form with unsaved edits must not misleadingly
claim that its displayed values match the public version.

## Unified editor status area

Replace the disconnected introductory paragraphs, crawl notes and publication
badge at the top of the editor with one consistent status area. Use the same
spacing, typography and icon treatment for each status. Decorative icons must
not replace text or be the only way to distinguish a state.

Separate editorial state from the site's current public state:

- **Publication / На сайте**: whether an active public page exists.
- **Draft / Черновик**: whether saved unpublished changes exist; explain when
  visitors still receive the previous version.
- **Unsaved edits / Не сохранено**: form changes not yet saved, distinct from
  a saved unpublished draft.
- **Sitemap / Карта сайта**: whether the active public address is included,
  with a concrete reason when excluded.
- **Crawler access / Доступ поисковых роботов**: the effective crawl permission
  for the currently published address.

Keep primary publication/draft information prominent. Secondary sitemap/crawler
details belong together, with contextual help rather than repeated paragraphs.
Make it clear which statuses describe the live page and which describe the
editable draft. Maintain this hierarchy across all page-editor panels.

Use one column on mobile and two columns from the shared tablet breakpoint
(768px) upward, keeping the status area compact vertically. Allow status text
to wrap without horizontal overflow and preserve the same logical reading and
keyboard order in both layouts.

## Changed fields and published values

Mark fields whose saved draft values differ from the active public page.
Cover Main, SEO, Open Graph and TV fields. Indicate affected tabs too, so hidden
panels do not conceal unpublished changes. Follow-up approved on 2026-11-10:
use _editorial-unsaved and _editorial-changed field styles without adding inline
status text below individual fields. Editing must not shift subsequent fields.
Keep the shared status area and accessible tab markers.

## Published-form view

Use one form-level toggle **Показать опубликованное** instead of the previously
suggested **Показать изменения** action or separate per-field comparison controls.
Show the toggle only when a public version exists and the editable field values
differ from it, including saved drafts and unsaved edits. Hide it when values
match or the page has never been published.

Clicking it displays the values currently published on the site in the same form
and panels. Mark the mode clearly as **Опубликованная версия**. All fields are
read-only, explicitly **not disabled**: text remains legible, focusable/selectable
where appropriate and available for copying. Inputs/textareas use readonly;
controls without a native readonly mode require an accessible read-only
presentation, including image/file selectors, selects and compound TV controls.
Do not simulate the mode by greying out a disabled form. File selection, clearing
and other mutations must not run in this mode.

The same toggle becomes **Вернуться к редактированию**. Its visibility in public
view is based on the preserved editable values, not the public values currently
displayed; the return action must remain available. Returning restores the exact
editing buffer, including unsaved edits, selected panel and relevant scroll
position. Inspecting the public version must not save, restore, publish or replace
the draft. Saving/publishing must not accidentally submit the displayed public
snapshot as the editable state.

Long text remains readable; images/files show the selected item and output size;
compound TV values use their ordinary user-facing representation instead of raw
JSON. Distinguish a saved unpublished difference from a new unsaved form edit.
An unpublished page has no public comparison value: explain this explicitly
rather than treating an absent public version as an empty published field.
Preserve meaningful distinctions between absent, empty, null, false and zero
where the field contract makes them distinct.

## Stable page-editor action area

Rework the editor header/actions so its geometry does not depend on the page
title's length or whether the published-view toggle is visible. Switching pages
with short/long titles, making the first edit, reverting the final difference and
switching view mode must not push the action area or the page content vertically.

Reserve a stable layout slot for the conditional toggle, sized for the longer
of its two labels in the selected language. When hidden, its slot preserves the
toolbar geometry without leaving an invisible focusable button. Do not hide the
toggle inside a menu when it is applicable.

Owner-approved layout: put the single-line page title in its own compact
header row, with ellipsis on overflow and access to the full title. Target a
32px total title-row height; do not inherit a 44px button-height minimum.
Keep vertical padding and spacing compact so the taller fixed editor area
does not unnecessarily reduce the scrollable form.

Follow-up approved on 2026-11-10: when the comparison action is absent, center
that title vertically beside the main actions. On appearance, move the title up
and fade in the comparison action over 160ms, keeping the toolbar, main actions
and form in place. Respect reduced-motion preferences. Balance the status area's
surrounding whitespace at 16px above and below instead of a large bottom margin.

Keep the reserved comparison slot below the title on the left. Center the fixed
primary action group on the right beside that stack; on narrow screens it moves
to a consistently reserved row below. Use the 36px compact button
variant throughout this action row. Move JSON-LD and Markdown into a clearly
labelled **Ещё** menu. Keep the primary **Сохранить и опубликовать** action prominent.
The full-site rebuild moves to Settings / General instead of this menu, as
specified below.

At narrower shared breakpoints, use a predetermined compact arrangement and
move secondary actions to the menu as needed. Any additional row required by
that responsive layout is reserved consistently; neither automatic flex wrapping
nor toggle appearance may change the row count within the same layout. The
ellipsis treatment, dedicated title/action rows, secondary-action menu,
responsive arrangement and reserved toggle slot are approved for 0.12.1,
alongside stable geometry and read-only public fields.

## Mobile follow-up for 0.13.0

Approved on 2026-11-11: below the shared desktop breakpoint (992px), place
the conditional published-version toggle in the scrolling status area, 8px below
the primary version status. Do not reserve an empty comparison row in the fixed
toolbar. Keep the 36px title and main action rows 12px apart on narrow screens;
from 768px the title and main actions can share one row. Keep the drawer and
editor navigation controls aligned.

When the comparison toggle appears or disappears during typing, preserve the
focused input or textarea's screen position, focus, selection and caret.
Compensate scrolling before painting; provide only the missing trailing scroll
space if a short form cannot otherwise keep the input in place. Cancel pending
compensation on teardown or focus changes. Preserve native anchoring for other
layout updates. Desktop comparison placement and reserved geometry remain as
specified above.

## Exact button heights

Introduce a reusable compact button size, **36px** total height including borders.
Use it for the page editor's action area, with consistent primary, secondary,
menu and icon-button treatments. This is an additional size variant; preserve
the normal button size for other contexts instead of shrinking all buttons.

Normalize the normal variant to exactly **44px**, replacing fractional effective
heights such as 44.8px. Both variants must have integral CSS-pixel heights with
explicit, compatible line-height, padding and border-box sizing. Do not rely on
fractional inherited line-height to determine the control's box. Preserve
readability, focus indicators and the existing visual hierarchy.

## Full-site rebuild in Settings / General

Move the existing standalone **Опубликовать весь сайт** action out of editor
toolbars to **Настройки -> Основные**. Label it **Пересобрать сайт** so its name
describes the current behavior. This relocates/renames the same full-publication
operation; do not create a second equivalent backend workflow.

Put explanatory text directly beside or above the button:

**Заново собирает все опубликованные страницы и создаёт самостоятельную
публикацию, которой не нужны файлы предыдущих публикаций.
Неопубликованные черновики страниц не публикуются.**

The operation uses published page versions, current saved templates/chunks/
Snippets, newly computed Build values and newly built frontend resources.
It is distinct from publishing all editable page drafts. Preserve existing
authorization, atomic activation and failure behavior.

Verify generated release-qualified asset references stay within the completed
full rebuild. A site may still reference its public media library or external
resources; independence here specifically means no dependency on older release
directories for CMS-generated resources.

## Clear robots.txt wording

Remove the standalone phrase **Правила из опубликованного robots.txt. Черновик
вступит в силу после публикации.** It does not identify whose draft is meant
and mixes a crawl-policy source with the current page's editorial state.

Use a concise result, for example **Доступ поисковым роботам: разрешён** or
**Доступ поисковым роботам: запрещён**, with the applicable reason.
Explain the source in contextual help: **Проверено по файлу robots.txt, который
сейчас действует на сайте.** Publishing the robots.txt document is what changes
those file rules; do not imply that publishing an unrelated page does so.

When robots.txt itself has unpublished edits, say explicitly **Изменения файла
robots.txt ещё не опубликованы**. When no public robots.txt exists, state that
fact without presenting the current page's draft as the source of crawl rules.
Crawler permission is distinct from the page's noindex setting, sitemap inclusion
and actual indexing by a search engine; do not label permitted crawling as a
guarantee that the page is indexed.

## Publication semantics

Consider the complete page-owned editable state, including content, H1, SEO,
Open Graph, rendering settings and TV values. A timestamp change or saving the
same values does not by itself constitute unpublished content. Shared element
changes and time-dependent public data are separate from a page's own draft.

Clear the indicator only when the corresponding page state becomes active on
the site. Failed or cancelled publication must not clear it. A later draft edit
must remain indicated even if publication of an earlier saved state succeeds.

The existing **Publish entire site** action rebuilds published page versions;
it does not promote page drafts. That action must not clear a draft indicator
when the active page still differs from its saved draft. **Save and publish**
for the page activates its saved state under the existing publication contract.

The application owns this publication/draft distinction. HTTP and administration
adapters present the result without recreating persistence or comparison rules
in the UI. Preserve the existing Hexagonal Architecture boundaries.

## Publication defect: prepared TVs in page catalogs

**Required fix for 0.12.1**, explicitly scheduled by the owner on 2026-11-10.
Acceptance: publishing the home/catalog page again must preserve card images
and descriptions without requiring a full-site rebuild as a repair step.

The release must also preserve prepared public TV values in publication catalogs.
A full build currently prepares values for rendering but omits them when saving
the manifest's published-page summaries. A later single-page publication reuses
those summaries for other pages. Publishing a catalog page can therefore freeze
missing images and empty teasers even though raw TV references remain correct
in the database and media files are available.

Preserve the complete published catalog through full and incremental publication.
Handle existing summaries that lack prepared TVs without substituting editable
draft values. Build-time consumers must receive consistent public values.
Do not resolve this by reading drafts during public rendering, removing snapshot
boundaries or treating a cache purge as a rebuild of frozen Build results.

Add a focused regression for full publication followed by single-page publication
of a catalog consumer: images, responsive outputs, alt text and teasers must stay
present, with cross-site and draft visibility unchanged. Verify that publishing
an unrelated page does not corrupt the catalog and that a later full rebuild
retains enough catalog data for subsequent incremental releases.

## Acceptance scenarios

Verify first publication, a changed draft of an existing public page, unchanged
draft saves, SEO/Open Graph/TV-only edits, successful and failed publication,
whole-site rebuilds with pending drafts, edits concurrent with publication,
page switching and reopening the editor. Drawer and editor status must agree
for the same page and remain scoped to the selected site.

Also verify header hierarchy and icons, keyboard/screen-reader access, narrow
layouts, changed-field/tab indicators and read-only comparisons for text,
images/files and compound TV values. Cover unsaved form edits, meaningful empty
values, pages without a public version, robots.txt changes independent of page
drafts, absent robots.txt, blocked crawling, noindex and sitemap exclusions.
Verify the published-view toggle with saved and unsaved differences, exact
restoration of the editing buffer, readonly rather than disabled controls,
keyboard/copy behavior, no mutations while inspecting public values, and public
activation changes while the editor is open. Cover short/long titles, first/last
field differences, both toggle labels, all shared breakpoints and both languages;
the toolbar and content position must remain stable when the toggle appears,
disappears or changes mode. Verify compact title-row geometry and exact 36px
compact / 44px normal button heights at normal zoom on DPR 1 and DPR 2 displays.
Check the relocated Settings / General rebuild action, its explanatory text and
unchanged draft/publication semantics.
