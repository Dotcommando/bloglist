# Локальная проверка админки перед минорным релизом

[English version](admin-release-tests.md)

Один раз перед выпуском каждой минорной версии на исходниках кандидата выполните:

```sh
npm run test:release:admin
```

Нужны закреплённые в репозитории Node/npm, зависимости после `npm ci`, отдельная
тестовая MongoDB с поддержкой транзакций и установленный Chrome/Chromium/Edge.
Задайте `ZARYA_TEST_MONGO_URI` и `ZARYA_TEST_BROWSER_EXECUTABLE` в окружении или
локальном `.env`. Без этих параметров команда завершается ошибкой. Она не запускает
базу данных или постоянное приложение владельца.

Команда один раз собирает CMS и админку, затем запускает выбранные тесты через
Vitest и Playwright в headless Chromium. Независимые файлы выполняются максимум
в шести процессах; зависимые шаги одного сценария идут последовательно. Число процессов
можно изменить и сравнить время на своей машине:

```sh
npm run test:release:admin -- --maxWorkers=2
```

Связный сценарий создаёт сайт с нуля через настоящую админку: первую страницу,
шаблон, чанк, простые сниппеты, оригинальные и адаптивные изображения, определения
и значения TV. Затем проверяет опубликованный сайт, SEO/OpenGraph, noindex и
sitemap, favicon, виртуальные папки и переносы адресов с редиректом и без.
Остальные выбранные тесты проверяют формы, мобильные экраны, клавиатуру и фокус,
ошибки/отмену, конфликты версий, резервные копии и предпросмотр исходников,
операции с файлами и пагинацию. Часть проверок интерфейса использует управляемые
HTTP-фикстуры; реальное взаимодействие компонентов проверяют связный сценарий и
интеграционные HTTP-тесты. У каждого независимого файла свои тестовые данные.

Перечень находится в [vitest.config.admin-release.ts](../../vitest.config.admin-release.ts).
Он охватывает Страницы, Шаблоны, Чанки, Сниппеты, TV-поля, Файлы и URLs. Это
ограниченный релизный набор, а не доказательство отсутствия любых дефектов CMS.

[Проверка пробелов покрытия](../changes/0.16.0/admin-site-journeys/70-coverage-gaps.md)
сопоставляет действия с тестами. Дополнительно проверяются вложенные параметры и
значения false/0/null, фазы/кеш/контракты сниппетов, просмотр сохранённых и
опубликованных Markdown/JSON-LD без потери черновика, все типы и значения TV по
умолчанию, обязательные поля и конфликт двух редакторов. Для Файлов проверяются
ошибка посередине очереди и повторная загрузка, замена содержимого без изменения
адреса, буфер обмена и скачивание. Для страниц — независимое исключение из sitemap
и очистка SEO/OpenGraph; для URLs — занятый адрес, отмена несохранённого ввода и
перенос вложенных страниц без редиректов. Прокрутка деревьев при выборе проверяется
на настольной и мобильной ширине в том же запуске.

Все дополнительно перечисленные [сценарии N01-N21](../changes/0.16.0/admin-site-journeys/80-remaining-scenarios.md)
теперь проверяются с реальным сервером: ручной порядок и язык страницы, вложенные
контракты и выполнение Build/Request-сниппетов, исправление ошибки TypeScript,
переназначение TV и устаревшие версии каталога/медиатеки, замена документов и всех
вариантов изображений, вложенные папки, конкурирующие редакторы файлов и отказы
при изменении адресов/редиректов. Для каждого из семи редакторов проверяются обрыв
до записи, таймаут, потеря ответа после записи и истечение настоящей сессии.
Проверки сверяют фактические данные сервера и явное восстановление без автоповтора.

В тестовых приложениях отключена посторонняя фоновая доставка. Сохранение,
транзакции, компиляция, обработка файлов и публикация остаются настоящими. Только
подготовка Request-режима и дополнительного языка использует локальную композицию,
поскольку в этих рабочих областях нет соответствующих контролов. Таймаут
воспроизводится управляемым истечением сигнала запроса без ожидания 15–120 секунд.

Результаты и длительности сохраняются в `.tmp/admin-release-results/report.json`.
На рабочей Windows-машине с 20 доступными логическими CPU расширенный набор из 164
проверок в 28 файлах прошёл в шести процессах за 199,61 с, со сборкой — за 211,0 с.
Финальный кандидат описан в [протоколе проверки](../changes/0.16.0/admin-site-journeys/50-verification.md). Это
измеренный ориентир; длительность на других машинах может отличаться.
При ошибке связного сценария рядом появляется Playwright trace `zarya_test_*.zip`:

```sh
node node_modules/playwright-core/cli.js show-trace .tmp/admin-release-results/TRACE.zip
```

Локальные отчёты и trace не включаются в Git. Trace может содержать синтетическую
сессию. Автоматических повторов нет: ошибка должна оставаться видимой. Фильтры
Vitest можно передавать для диагностики, но перед релизом нужен полный прогон
команды без фильтров на окончательном кандидате. Публикация релиза — отдельная
операция.
