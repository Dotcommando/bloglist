# Домены и TLS

[Установка](INSTALLATION.md) · [English](../en/tls.md)

Hostname backend указывает на IP сервера. Caddy слушает 80/443, автоматически
получает и продлевает публичный сертификат. Сохраняйте тома `caddy-data` и
`caddy-config`. DNS и ACME-проверки должны быть доступны; перед загрузкой Worker
проверьте логи Caddy и прямой HTTPS.

Канонический публичный hostname является Custom Domain Worker: Cloudflare создаёт
для него DNS-запись и браузерный сертификат. Обычная A/CNAME-запись того же имени
может помешать подключению даже после загрузки кода. Устраняйте только известный
конфликт, предварительно сохранив старое значение. DNS backend остаётся отдельным.

Для канонического `https://www.example.test` проверьте четыре сочетания:

| Запрос | Результат |
| --- | --- |
| `https://www.example.test/path?q=1` | Канонический документ |
| `http://www.example.test/path?q=1` | Постоянный редирект на HTTPS |
| `https://example.test/path?q=1` | Постоянный редирект на канонический www |
| `http://example.test/path?q=1` | Постоянный редирект на канонический HTTPS www |

Для корневого домена отдельно настройте редирект в Cloudflare с проксируемой
DNS-записью; сохраняйте путь и query. Если каноническим выбран корневой домен,
поменяйте роли www и корня. Worker обслуживает точный hostname и не получает
другой адрес только потому, что он находится в той же зоне.

Если DNS backend проксируется, используйте Full (strict) с действующим серверным
сертификатом. Не перенаправляйте backend обратно на публичный Worker.
Вне localhost оба origin требуют HTTPS и должны различаться.

`ZARYA_ADMIN_AUTH_ORIGIN` задаёт только начальный origin админки:
при первом запуске CMS сохраняет его в базе. Позднее откройте «Настройки» → «Общие»
и измените «Адрес админки», например на `https://www.example.test/admin/`.
Настройка общая для всех сайтов. Изменение `.env` не перезаписывает сохранённый адрес.

Сначала настройте HTTPS и проксирование `/admin/*` и `/api/admin/*` к этой установке.
Worker CMS уже выполняет такое проксирование. CMS проверяет домен, TLS и ответ своей
админки через новый адрес; при ошибке сохраняет прежний. После сохранения адрес
переключается без перезапуска, прежняя cookie теряет силу, браузер открывает новую
админку для входа. Старый адрес админки перенаправляет на новый; старый API-host
отклоняется. `Backend origin` во вкладке «Деплой» остаётся адресом связи Worker
с backend; DNS backend менять не нужно. Подмена Host и служебные заголовки Worker
не предоставляют административных прав. См. [ADR 0058](../../adr/0058-installation-admin-address.md).
