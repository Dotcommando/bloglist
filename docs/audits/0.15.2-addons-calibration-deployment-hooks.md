## Security and recovery assessment

Checked applicable admission, actor/site/global identity, private versus public
assets/configuration, input/JSON/archive/path limits, installed-code/dependency
identity, current grants and forbidden command authority, scoped queries,
optimistic writes/registry generations, exact receipt reconciliation, resource
exclusion, restore state and asynchronous ownership. Failure tests assert absence
of reads, compilation, download, command or write as appropriate; positive controls
prevent an implementation that rejects everything from passing.

Known rejection is not an uncertain effect. An expired external ownership lease
does not authorize upload replay. A completed check's unused read may acknowledge
cancellation; an unexpected late failure still propagates. Worker CPU deadlines
remain distinct from owned host-I/O cleanup under dependency deadlines.
Internal locks, sessions, workers and staging remain code-owned. An actual private
storage outage can still fail the request; no log-only success or inaccessible
JS-object notification is presented as recovery.

The pinned driver's abort behavior was inspected before the abort regression:
ordinary command failures are handled there, but MongoRuntimeError can propagate.
The test injects that supported error and proves host behavior; it does not claim
a production outage, a post-commit session leak or a security exploit.
