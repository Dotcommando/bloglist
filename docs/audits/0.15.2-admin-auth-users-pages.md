## Security assessment and exclusions

Verified applicable checks: credential/secret omission, unknown-account/source
admission, blocked/expired/revoked/account-version fencing, owner-bound session
cursors/revocation, trusted actor rather than caller-controlled actor, last-admin
serialization, early rejection before body/expensive work, foreign site/page
denial, stale writes and rollback, and separation of drafts from active publication.
Failure tests assert forbidden effects/state preservation in addition to errors.

The actual pinned MongoDB driver session lifecycle was inspected, including
post-commit state and endSession's finally release. Broad rollback/endSession
catches in page adapters were investigated, but no supported post-commit JS
resource leak or actionable operator intervention was demonstrated. Arbitrarily
rejecting a mock endSession is not evidence of that defect. Resource ownership
remains in code; the owner's rejected dead-end operator proposal is now an explicit
[counterexample in error design](../cms-development/feature-design.md#error-outcomes-and-recovery).
No new notification/retry flow was invented.

No production installation was probed. No whole-product security certification,
advisory scan, exhaustive fuzzing, live external service, deployment, release image
or unrelated UI/Safari audit is claimed. No dependencies, executable-authority
contracts or UI behavior changed. Browser checks executed inside the selected
auth/publication integrations cover persistent cookies/compiled static-export
interaction only. These limits do not leave a required check for the changed
adapter behavior pending.
