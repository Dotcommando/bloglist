# Installation, JSON-LD, media and publication: 0.15.2 review

Date: 2026-11-18. Baseline: `b5edf6842469155a08e767d94fb66f5f64fdf59f`
(previous auth/users/pages review committed at the owner's request). Target/branch:
`0.15.2`, unpublished; package metadata remains 0.15.1.
Scope: all **38 operations** in installation (2), json-ld (5), media (16) and
publication (15), with involved adapter methods, actual composition and failure
ownership. Followed the [existing-feature review](../cms-development/existing-feature-review.md)
and [dossier](../changes/0.15.2/installation-jsonld-media-publication-qa/10-behavior.md).

## Findings

**11 new confirmed bugs corrected: 9 production and 2 QA bugs; 0 confirmed
vulnerabilities.** The [canonical inventory](../changes/0.15.2/installation-jsonld-media-publication-qa/50-verification.md#defect-inventory)
links every card. It excludes previous-review findings, added characterization,
intermediate fixture/implementation mistakes and unconfirmed concerns.

Production corrections preserve existing product policies: distinguish local
dependency failure from invalid input, fence media projection installation by the
current journal version under the writer lock, own staging resources from
creation, recover preview startup, and stream frontend/export assets while
observing asynchronous siblings. The neutral projection check returns whether it
installed output; filesystem/ODM details remain inside adapters. The offline
migration caller checks its captured completed version under that same lock.
No new operator workaround, fallback, dependency upgrade, authority, automatic
media processing, migration checksum change or deployment was introduced.

## Security and failure assessment

Applicable checks cover trusted actor/site admission before protected work,
private originals versus named public output, absent/foreign identifiers, scoped
catalogs and retained releases, bounded streams and safe paths, SSRF candidate
rules for address probing, no remote JSON-LD identifiers, safe generated scripts,
public/draft separation, guarded concurrent writes, receipts, and owned cleanup.
Tests check forbidden effects and durable output as well as error values.

A storage error is technical; malformed user content/candidate proof retains
current validation behavior. The code disposes owned temporary state or preserves
a durable retryable journal/output. It does not tell an operator to manipulate an
in-process MongoDB session or remove a lock while a live owner can still act.
Unknown commit/abort does not authorize replay. No supported post-commit session
leak was demonstrated from the pinned driver; redundant catch removal and abort
characterization are not a new defect card.

Generic asset partial failure can leave a private unreferenced immutable object,
as the existing contract states; this review adds no speculative garbage collector.
Media movement can commit before source-reference repair and supports the
documented same-name repair retry. Those approved outcomes are not reclassified
as bugs. Current codec/plan/migration-format tests protect real contracts.

## QA correction and test value

Protected admin bundle HEAD fixtures now explicitly authorize their synthetic
actor. Installation fixtures provide the required Vite entry manifest and assert
both current path-scoped secure cookies. Media tests select their own IDs and
fixtures, preserve unrelated files, recover without a previous browser test, and
prove the real private original existed before asserting deletion. Real access
policy and production composition were preserved.

Removed the two-case duplicate `published-catalog.spec.ts`; its unique later-call
active-pointer case moved into the stronger existing catalog test. A misleading
store test title was corrected to its actual owned empty-read guarantee. Other
tests were retained when they exercise current behavior, including wire formats
and migrations; the review did not delete tests merely for mentioning an enum.

## Checks and limitations

**333 unit/adapter/architecture tests and 39 real integrations passed (372 total).**
Six Files UI/onboarding cases were deliberately outside the backend name filter.
Format, lint, server/Svelte typechecking and build passed. The build reports the
existing informational admin chunk-size warning. Exact manifests, RED/GREEN
classification and reproduction commands are in the [verification record](../changes/0.15.2/installation-jsonld-media-publication-qa/50-verification.md).

MongoDB used an owned loopback replica set, tmpfs and task label; fixture roots,
databases and listeners were isolated. The final state records its removal and
documentation consistency/link/whitespace checks. No owner database/service was
stopped and no persistent owner app was started.

Excluded: unrequested full suite, exhaustive fuzzing, all browsers/OSes,
dependency advisory scan, live internet address probing, production data,
Cloudflare upload/deployment, complete rendering engine and coordinator/fork-drain
audit. Existing configured publication browser checks did execute. Snippet
republication has substantive unit and shared real release-adapter evidence,
without a separate live snippet-update end-to-end claim. Zero confirmed
vulnerabilities means none reproduced in this bounded review, not whole-CMS
security certification.
