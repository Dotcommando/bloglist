# CMS 0.13.0 file-management review

Date: 2026-11-11.

Scope: candidate changes from the 0.12.2 baseline through `a145850`, including
upload metadata forwarding, file moves and renames, source-reference updates,
missing-media editors, responsive controls and output-size metadata.

## Corrected findings

- A relative path embedded in a foreign URL's query or fragment could be
  rewritten. Complete absolute and protocol-relative URL ranges now prevent
  nested matches while retaining explicitly scoped site-origin matches.
- An ASCII source filename produced duplicate encoded/decoded lookup keys;
  the decoded destination overwrote its encoded counterpart. Destinations now
  retain URL encoding and encode parentheses for unquoted CSS `url()` values.
  Later moves recognize that encoded representation too.
- Prefix matching could change a different filename containing a closing
  parenthesis or a space, a Unicode-prefixed relative address, or an escaped
  source literal. Boundary checks now preserve these values. Srcset descriptors
  and adjacent CSS URLs retain focused regression coverage, including mixed
  absolute/relative srcset candidates without extending URL ranges across them.

These findings affected source integrity and could break links or unrelated
external URLs; they did not establish an authentication bypass.

## Boundary and security checks

The changed domain, application and port contracts retain inward dependencies
and contain no new framework, ODM, transport DTO or provider types. Reference
updates call the existing source/TV inbound contracts with the current session,
version guards and backup behavior. No new direct cross-capability collection
writes or HTTP use of local-operator authority were found.

The authenticated HTTP regression checks anonymous rejection (401), foreign
Origin rejection (403), invalid reference-update flags (400), and cross-site
file-identity rejection (404), preserving catalog versions after denied writes.
It then renames to a filename containing spaces and parentheses, verifies
guarded template/chunk/TV changes and fetches the encoded public variant.

Source inspection found no new authored-source execution or external fetching
in missing-file warnings. New labels use escaped text. Source saves remain
sequential and awaited; a rejected save stops later writes.

Verification uses deterministic unit fixtures and isolated HTTP/database
composition. The established partial-commit semantics in ADR 0079 remain:
moving a file and subsequently saving its sources is not one atomic transaction.
This review covers the candidate code paths, not a production penetration test
or a dependency-advisory audit.
