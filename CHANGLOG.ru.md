# История изменений

[English version](CHANGELOG.md)

## Не выпущено

Размер подписей медиатеки адаптируется к экрану, а сокращённые имена
[сохраняют окончание и расширение](docs/defects/admin/file-label-extension-hidden.md).

[Отдельный заголовок «Дамп сайта»](docs/defects/admin/site-dump-group-heading.md)
объединяет карточки экспорта и импорта.

Из карточки файла можно вернуться в папку по ссылке «Файлы» в хлебных крошках.

При обновлении медиатеки результаты остаются на месте под
[общим индикатором загрузки](docs/defects/admin/media-browser-refresh-shift.md).
Панель фильтров использует компактные элементы управления CMS.

Фильтры медиатеки сгруппированы, [пагинация выровнена](docs/defects/admin/media-browser-control-alignment.md),
размер страницы вынесен в «Настройки → Основные».
В дампах поясняется действующее ограничение доступа к категориям.

Создание и восстановление дампа установки разделены на
[две карточки](docs/defects/admin/installation-dump-form-layout.md) с общим компонентом выбора файла CMS.

Метаданные Files и журналы восстановления хранятся в отдельных записях.
Изменения публичных файлов применяются адресно. Files и окна выбора
используют общий браузер папок с серверной пагинацией. SDK 0.7.0 добавляет
чтение метаданных, создание папок и потоковую загрузку ограниченными пакетами.
Каталог сохраняет [порядок записей](docs/defects/media/split-catalog-order-drift.md),
а параллельные загрузки пережидают [краткую блокировку](docs/defects/media/batch-storage-writer-contention.md).
Во время подготовки и установки замены публичный URL отдаёт прежний файл.
Папки и страницы загружаются по запросу. SDK получает метаданные одним
пакетом. Объявленные ссылки аддонов учитываются при удалении и восстановлении.
Устранена [гонка при публичном чтении](docs/defects/media/public-file-read-catalog-contention.md).
Блокировка восстанавливается после [остановки процесса](docs/defects/media/abandoned-site-writer-marker.md).
Ссылки аддонов восстанавливаются [после замены файла](docs/defects/media/addon-files-checksum-restore.md).
Экспорт сохраняет записи со [ссылками на удалённые файлы](docs/defects/media/addon-export-dangling-file.md).
Можно [повторить обновление ссылок](docs/defects/media/file-move-reference-retry.md).
Редактирование проверяет [версию файла](docs/defects/media/file-card-catalog-revision.md),
а окно выбора проверяет [MIME-тип до сохранения](docs/defects/media/picker-mime-after-save.md).

## CMS 0.16.1 (2026-11-21)

В карточке аддона видны активная версия и источник обновлений. Из карточки
можно обновиться через GitHub или из файла и подключить GitHub к совпадающему
пакету. [Завершённое обновление](docs/defects/addons/completed-update-shown-as-candidate.md)
после сверки исчезает из рабочей формы.

[Кнопки управления аддоном](docs/defects/addons/card-action-vertical-alignment.md)
выровнены по верхнему краю строки.

[Индикатор загрузки при работе с аддонами](docs/defects/addons/card-operation-progress-missing.md)
показывается на карточке или рядом с выполняемым действием.

[Имя файла аддона](docs/defects/addons/package-picker-grouping.md) сгруппировано
с кнопкой выбора, а действия проверки и отмены отделены отступом.

На общей кнопке «Обновить» установлена более отчётливая
[иконка обновления](docs/defects/admin/refresh-glyph-legibility.md).

CMS передаёт аддонам [признак системной страницы](docs/defects/admin/addon-page-system-role-dropped.md).

[Браузерные тесты загрузки аддонов](docs/defects/qa/addon-browser-promise-target.md)
совместимы с целевой версией TypeScript для релиза.

## CMS 0.16.0 (2026-11-20)

Параллельное создание элементов рендеринга с разными зарезервированными
ключами повторяет прерванную транзакцию при конфликте записи общих данных.
См. [исправление](docs/defects/hooks/numbered-element-write-contention.md).

Аддоны можно устанавливать и проверять их обновления из закрытых репозиториев
GitHub через GitHub App с правом чтения. Ключи PEM можно заменять в настроенном
каталоге без перезапуска CMS. Подготовка Compose подключает каталог ключей
автоматически, когда задан Client ID.

System Admin может проверять и устанавливать обновления из GitHub в карточках аддонов.

Счётчики аддонов помещаются внутри кнопок меню. Зазор под шапкой убран.
См. [исправление](docs/defects/addons/menu-badge-spacing.md).

Manager по умолчанию может публиковать отдельные страницы и применять изменения маршрутов.

Действия аддонов регистрируются вместе с активным runtime. Экраны можно
делегировать через роли. CMS проверяет право на запрос до чтения тела и повторно
проверяет актуальный доступ при записи.

Site Admin может создавать и восстанавливать полные дампы назначенных сайтов.
Для System Admin добавлены отдельные действия с дампами установки. Во всех
вкладках настроек выровнены отступы заголовков и обновлено оформление групп
полей доступа.

Код админки разложен по функциям, а строки интерфейса вынесены в типизированные
словари. Переключатель языка строится из реестра локалей.

Добавлены SystemAdmin, SiteAdmin и Manager, пользовательские роли и группы
доступа на сайте. Разрешения выдаются на action целиком. Для поддерживаемых
действий со страницами, чанками и сниппетами доступны области «Свои» и «Группы».
Встроенные группы Global и Site используют назначения ролей. Сервер проверяет
разрешение на действие для обеих административных ролей.
Скрипт создания администратора принимает `--site-id` для назначения Site Admin
на конкретный сайт.
В разделе «Доступ» появились вкладки, настройки разрешений по доменам с
синхронизацией одинаковых действий и форма создания пользователя с выбранной
ролью. У Manager есть редактируемая политика по умолчанию. Меню и элементы
рабочих разделов зависят от доступных действий.
Ссылка «Создать страницу по адресу /blog/» в URLs подставляет путь выбранной
виртуальной папки. Для показа ссылки нужны права на список URLs, создание
страниц и материализацию URL.
В настройках роли и при открытии ссылки на страницу CMS поясняет, когда
требуется право чтения черновика. Если это право не охватывает страницу,
API возвращает [только подтверждение записи](docs/defects/pages/draft-update-response-read-scope.md).
Редактор страницы и настройки роли объясняют, когда для перемещения нужно
право чтения списка страниц.
Редактор объясняет, почему недоступны настройки публикации. Сохранение черновика
и просмотр опубликованных Markdown и JSON-LD проверяют свои права.
Пользователь с правом публикации может опубликовать сохранённый черновик по
назначенному адресу и с сохранёнными настройками шаблона.
Настройки роли поясняют охват общесайтовых сведений. Ссылка из каталога URLs
в редактор страницы учитывает право чтения конкретного черновика.
Значения TV доступны для чтения без настроек публикации. Вкладка объясняет,
какое право нужно для их сохранения.
Ссылки из страниц и шаблонов открывают связанные профили JSON-LD. Право чтения
каталога позволяет просмотреть профиль и его привязки.
Open Graph показывает сохранённый адрес изображения без доступа к библиотеке.
Для приватных миниатюр в селекторе нужно право чтения содержимого файлов.
Настройки роли подсказывают, когда для предпросмотра нужно чтение черновика.
Ссылка на настройки JSON-LD требует права чтения каталога профилей.
Без права пересборки сайта основное действие в редакторе исходника сохраняет
черновик. Подтверждение объясняет, кто может применить изменения.
Предпросмотр исходника предлагает только доступные страницы и поясняет, если
не хватает чтения страницы или доступа к готовому предпросмотру.
Список использований исходника открывает только доступные для чтения объекты
и поясняет, какое право нужно для остальных переходов.
В разделе «Файлы» и настройках роли CMS поясняет, почему загрузке файла и
созданию папки нужен доступ к списку библиотеки.
Карточка файла поясняет, когда для переименования, перемещения или удаления
нужно право проверки использований. Имя и метаданные остаются доступны.
Подтверждение переноса показывает прежние и новые адреса. Ссылки на редакторы
учитывают права чтения. Перенос [обновляет ссылки в сниппетах](docs/defects/media/file-move-skips-snippet-links.md),
сохраняя остальные правки черновиков и прежние публикации.
Карточка с метаданными файла подсказывает, какое право нужно для просмотра
приватного содержимого и скачивания.
Без права поиска URLs можно изменить путь, сохранив родителя, и поменять
код редиректа, сохранив его адрес назначения.
Карточка URLs показывает сведения о связанной странице и поясняет, когда для
открытия черновика нужно право чтения.
Если сохранённый маршрут ещё ждёт применения, CMS подсказывает, кто может
применить изменения. Для публикации маршрутов достаточно её отдельного права.
Основные настройки поясняют режим чтения. Пересборка использует сохранённые
настройки. После смены публичного адреса CMS подсказывает, кто обновит sitemap.xml.
Черновик обработчика Hooks можно создать без права подписки. CMS объясняет,
какого права не хватает для назначения, и [открывает сохранённую подписку](docs/defects/hooks/attachment-editor-navigation.md).
В управлении аддонами CMS объясняет, для каких экранов ещё не настроили права.
Такие экраны и их ресурсы доступны администраторам в управлении аддонами.
Исправлен [размер кнопок действий над аккаунтом](docs/defects/admin/account-action-target-size.md).
Заголовок раздела «Доступ» [приближен к его вкладкам](docs/defects/admin/access-heading-spacing.md).

Добавлена локальная [релизная проверка админки](docs/cms-development/admin-release-tests.ru.md):
создание сайта с нуля через браузер и параллельные проверки Страниц, Шаблонов,
Чанков, Сниппетов, TV-полей, Файлов и URLs. Исправлены открытие TV по прямой
ссылке, фокус при мобильной валидации черновика и потеря несохранённого имени/папки
файла. Тестовые фикстуры приведены к текущим контрактам CMS.

После проверки покрытия добавлены вложенные параметры, просмотр сохранённых и
опубликованных документов, настройки сниппетов, значения TV по умолчанию и
конфликты, восстановление очереди файлов, очистка SEO/OpenGraph и ошибки/переносы
URL. В релизный запуск включены существующие проверки прокрутки деревьев.
Исправлены [редактирование типа/значения элемента массива](docs/defects/admin/array-item-parameter-kind-lost.md)
и [доступные подписи значений TV по умолчанию](docs/defects/admin/tv-default-label-collision.md).

Оставшиеся сценарии админки покрыты настоящими браузерными проверками: выполнение
вложенных контрактов после публикации, исправление TypeScript, переназначение TV
и устаревшая медиатека, замена документов/вариантов изображений, вложенные папки,
конкурирующие редакторы файлов, конфликты URL и отказ циклическому редиректу.
Проверяется восстановление после обрыва, таймаута, потери ответа после записи и
истечения сессии. Исправлены выбор страницы в фикстуре, область init-скрипта языка
и ожидание обновления поля, изолирована посторонняя фоновая доставка;
добавлены существующие реальные проверки версий TV
и кеша. [Матрица и доказательства](docs/changes/0.16.0/admin-site-journeys/80-remaining-scenarios.md).

## CMS 0.15.3 (2026-11-18)

Исправлена публикация страниц и маршрутов при наличии
[favicon в сохранённой Request-странице](docs/defects/publication/retained-favicon-rejected.md).
Публикация из админки теперь [подхватывает настроенный favicon](docs/defects/publication/admin-favicon-source-missing.md).
После частичного сбоя [редактор новой страницы уточняет состояние URL](docs/defects/admin/new-page-partial-publication-state.md),

## CMS 0.15.2 (2026-11-18)

Кнопке версии возвращено общее пунктирное подчёркивание действия внутри экрана
с сохранением закрытия Popover и клавиатурного управления. Выполнена подготовка
проверок релиза; [результаты](docs/changes/0.15.2/release-readiness/50-verification.md).

Окно версии CMS закрывается по Esc и клику вне него. Используется общий Popover
с сохранением клавиатурного фокуса, метаданных и границ мобильного экрана.
Исправлены устаревшие маршруты и ожидания responsive-теста настроек доставки.
Четыре браузерных сценария прошли; подробности — в
[проверке исправления](docs/changes/0.15.2/cms-build-info-dismissal/50-verification.md).

Версии CMS/admin/lockfile согласованы на 0.15.2; точный коммит и контрольная сумма
исходников фиксируются в проверяемом архиве независимо от состояния установки.

Целевая версия 0.15.2: проверены все 38 use cases add-ons/calibration/deployment/hooks
и используемые адаптеры. Исправлены 12 багов рабочего кода: полнота метрик и журнал
калибровки, порядок подписок и жизненный цикл hook-команд/worker, проверка backend
и освобождение ресурсов доставки, сохранение ошибок и очистка add-on. Реализация
каталога вынесена из DI-фабрики в исходящий адаптер. Прошли 288 целевых
unit/adapter/composition/architecture проверок и 26 интеграционных сценариев;
один неизменённый POSIX-тест helper исключён на Windows. Подтверждённых
уязвимостей нет. Подробности и карточки — в
[ограниченном аудите](docs/audits/0.15.2-addons-calibration-deployment-hooks.md).

Целевая версия 0.15.2: проверены все 38 операций installation/JSON-LD/media/publication
и задействованные адаптеры. Исправлены маскировка технических ошибок, установка
устаревшей медиапроекции, восстановление после ошибок подготовки каталогов,
блокировок и запуска предпросмотра, буферизация бинарных файлов и потеря
асинхронных ошибок ассетов. Исправлены QA-фикстуры актуальных контрактов и
принадлежности файлов; дублирующие проверки каталога объединены с сохранением
уникального покрытия. Зафиксированы 9 багов рабочего кода и 2 бага QA, прошли
333 целевых unit/adapter/architecture теста и 39 интеграционных сценариев;
подтверждённых уязвимостей нет. Подробности и карточки дефектов — в
[ограниченном аудите](docs/audits/0.15.2-installation-jsonld-media-publication.md).

Целевая версия 0.15.2: проверены все 22 операции admin-auth/admin-users/pages и
границы задействованных адаптеров. Исправлены ложные конфликты архивирования и
перемещения при отсутствующих полях документа и преобразование асинхронных ошибок
репозитория. Добавлены содержательные регрессии отката, безопасных профилей,
ошибок публикации и хранилища сессий. Исправлены устаревшие QA-фикстуры, удалены
проверки собственной имитации создания страницы, выдуманного DI-токена и лишние
инвентаризации методов. В [ограниченном аудите](docs/audits/0.15.2-admin-auth-users-pages.md)
зафиксированы 2 бага рабочего кода и 8 багов QA; подтверждённых уязвимостей в рамках
проверки нет. Стандарты дополнены требованием выполнимого выхода из ошибки и
конкретными примерами бесполезных тестов.

Общие стандарты разработки фич, проектирования, тестирования, безопасности и
проверки существующих возможностей собраны в `docs/cms-development/` и подключены
через AGENTS.md. Повторяющиеся требования перенесены из локальных инструкций и
разделов проверки README. Относящиеся к фиче интеграционные тесты должны пройти
до её завершения; первоначальный запуск после пяти use case отменён с
сохранением исторических решений.

Знания о фиче или исправлении сохраняются в `docs/changes/<version>/<slug>/`
с согласованной целевой версией; без версии допускаются только правки документации.
Один файл состояния содержит этап и шаг TDD в имени; отдельные файлы поведения, затронутого функционала,
проектирования, сценариев, проверок и решений. Для бэкенда закреплён цикл
RED/GREEN/REFACTOR с доказательствами запуска. Определены содержательные unit- и
интеграционные проверки; исключены тесты экспортов barrel-файлов, значений enum
и прочие проверки одних деклараций.
Добавлены примеры тестов без содержательных доказательств и полезные альтернативы:
проверки одних моков, повторение алгоритма в ожидании, проверки одного HTTP-статуса
или факта ошибки и подмена реальных интеграционных гарантий имитацией.

Для ошибок закреплены явный исход для пользователя/оператора, безопасный путь
продолжения и вопросы владельцу, если бизнес-поведение или подходящий прецедент
неочевидны. Добавлен `docs/defects/`: выборочные индексы областей и отдельные
карточки причин, регрессий и предотвращения повторных багов/уязвимостей. По
существующему аудиту shutdown внесены два исторических бага; новые runtime-проверки

Недоступность калибровки объясняется конкретным препятствием и способом исправления:
связь с helper, фактические квоты и ошибки получения состояния различаются явно.

Калибровка соблюдает общий CPU-бюджет БД и CMS во всех замерах и отклоняет запуск
без управляемых квот. Профили показывают все сайты компактными блоками с заливкой;
старые замеры при фиксированных ресурсах явно помечены в истории.

Контролы калибровки используют общее оформление админки. Подписи страниц,

в опубликованные маршруты выбранного сайта.

Добавлена калибровка работающих сайтов: CRUD профилей, точные доли запросов,
профили всей установки, критерии задержки по каждому сайту и история замеров.
В управляемом Docker подбираются процессы, дробные CPU БД и CMS и пул БД на
процесс, с отдельным генератором у Unix-helper. Нативно доступны профили и история;
запуск без управляемых квот отклоняется. Временное распределение журналируется
и восстанавливается при завершении, отмене и перезапуске. Добавлены вкладка
«Калибровка» и последние десять результатов с явным применением в «Основных».
См. [описание калибровки](docs/arch/resource-calibration.md).

Глобальные операции ресурсов явно проверяют действующего администратора установки;
HTTP-граница сразу отклоняет неконечный CPU-бюджет и неположительное число процессов.
Добавлены регрессии анонимных и отозванных сессий, подмены идентичности, CSRF,
перехвата WebSocket, prototype-payload, приватных файлов/процессов и ключа Unix-helper.
См. [проверку безопасности](docs/audits/0.14.0-resource-security.md).

Дробная CPU-квота Linux определяется без потери дробной части из-за округлённого
целочисленной оценки параллелизма, с учётом маски доступных CPU и cgroups v1/v2.
Рекомендации ресурсов и выбор режима дампа используют полный доступный бюджет.

При сбросе повторно используемого соединения координатора с процессом сайта
GET/HEAD без тела однократно повторяется через новое соединение до начала ответа.
POST, запросы с телом, ошибки нового соединения и частично переданные ответы не
повторяются. Реальные HTTP-тесты проверяют границу повтора, отмену и сохранённую запись.

Публикация проверяется непрерывными запросами к нескольким прогретым процессам:
статические и Request-страницы, завершение старых запросов, сохранение ресурсов и
ошибка подготовки версии. Добавлены регрессии долгих запросов, падения процессов
и координатора, недоступной MongoDB, одновременных сохранений, обрыва потоковых
передач и повторных изменений конфигурации. При ошибке записи сохраняется
последнее записанное распределение; временные файлы, записи завершённых процессов
и их обработчики удаляются. Падение замены во время завершения старого процесса
не оставляет пул неполным. Перекрывающиеся остановки ожидают одну операцию;
готовность после начала остановки отклоняется.

Рамки выделяют отдельные сайты в распределении ресурсов только при нескольких
сайтах. Общий блок процессов CMS отображается без рамки.

Лоадер применения ресурсов центрируется в видимой части формы при прокрутке и
изменении размера окна и остаётся заметным при быстром ответе. После завершения
кнопка явно показывает сохранённое состояние; новое изменение снова включает
сохранение. Пояснение о дампе связано с действием «Настройки / Дампы / Создать
дамп» в продакшене.

Максимум пула БД на процесс сайта меняется в «Ресурсах», в том числе при 1–2 CPU.
Процессы заменяются по очереди без перезапуска координатора; при ошибке запуска
нового процесса старый продолжает работать. Сохранённый и применённый размеры
показаны отдельно от служебного пула координатора, задаваемого при запуске.

HTTP-прокси переиспользует соединения координатора с процессами сайта и не передаёт
служебные заголовки соединения между сетевыми участками, устраняя исчерпание
TCP-портов под нагрузкой. Сбой фоновой проверки сессии сохраняет экран админки и
введённые значения, показывает предупреждение и автоматически повторяет проверку;
ответ HTTP 401 по-прежнему переводит на вход.

При применении распределения ресурсов показан круглый лоадер поверх формы.
Фоновое обновление не блокирует форму и не перезаписывает новые изменения или
результат сохранения. Ожидание запроса и тела ответа ограничено; потерянный ответ
проверяется по фактическому состоянию без зависания общего флага занятости.

При запуске явно сообщается о занятом HTTP-порте или файле координатора,
в том числе при работающем Docker-приложении, без вывода приватных деталей ошибки.

Один координатор непосредственно управляет процессами сайтов и дампов через
`fork`: завершением запросов, восстановлением после сбоя, отменой и очисткой
прерванного дампа. Размещение БД задаётся явно: управляемая локальная, отдельно
управляемая локальная или внешняя. CPU внешней БД не вычитаются из бюджета
машины приложения. Расчётные ограничения числа процессов по памяти и соединениям
убраны; рекомендация CPU остаётся предупреждением. Пулы MongoDB каждого процесса
настраиваются отдельно. См. [ADR 0083](docs/adr/0083-fork-supervision-and-database-placement.md).

[Состав релиза и критерии приёмки](docs/arch/0.14.0-site-process-allocation.md):
процессы CMS без PM2; все подключённые сайты, доступные CPU и распределение
ресурсов между сайтами в «Настройки / Общие». Сайт с двумя и более процессами
временно отдаёт один из своих процессов под дамп. Однопроцессный сайт использует
любой свободный остаток CPU, даже 0.1; без остатка дамп выполняется внутри процесса
сайта. По умолчанию лишние ресурсы остаются нераспределёнными.
Включены межпроцессная координация обслуживания и восстановления, управление
CPU-квотой MongoDB из админки через явно настроенную интеграцию с Docker,
включая дробные значения. Показываются число логических CPU и отдельный график
для каждого, с данными раз в секунду через авторизованный WebSocket с момента
входа в админку, без истории на сервере. Сбор прекращается после отключения
последнего администратора. Общее число
процессов рекомендуется по CPU-бюджету CMS с округлением вверх, без жёсткого
ограничения числа сайтов и процессов. Включено локальное нагрузочное тестирование
двух сайтов без изменения hosts, со сверкой метрик отдельных процессов.
Проверяются соблюдение числа процессов сайта и изоляция фриза его event loop
от процессов другого сайта, отдельно от исчерпания общих ресурсов.
Теги образов CMS/исполнителя синхронизируются с версией
релиза; оба Compose-файла используют проверенную MongoDB 9.0.8 с точным digest,
проверкой совместимости обновления и защитой от расхождения версий.
См. [ADR 0082](docs/adr/0082-site-process-allocation.md) и
[отчёт проверки](docs/audits/0.14.0-site-process-allocation.md).
Публикация релиза и обновление установок выполняются отдельно.
